# Maintainers and review authority

## Current maintainer

- Gautam R. Patil — founder and maintainer — `gautam@truscor.org`

The current single-maintainer state is a bus-factor and incident-response risk,
not a permanent governance goal.

## Permissions

Only a designated release maintainer may create a release candidate or request
publication. A security maintainer may coordinate embargoed fixes. A schema
maintainer may approve compatible experimental changes but cannot declare a
permanent 1.0 invariant without the published stability process.

No role can waive CI, DCO, confidentiality, provenance, dual-use, or disclosure
requirements. Founder approval remains required for first-release licence,
trademark, novelty-sensitive publication, and patent decisions.

## Succession

Before promoted launch, add at least one independent code reviewer and one
security-response backup, document protected-account recovery, and test a
release handoff. If maintenance stops, preserve signed releases, schemas,
compatibility kits, security advisories, and an archival repository snapshot;
do not silently transfer the project trademark or trust claims.
