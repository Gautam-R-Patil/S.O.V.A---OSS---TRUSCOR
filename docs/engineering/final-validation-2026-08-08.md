# SOVA OSS founder-vision implementation validation

Validated on 2026-08-08 with CPython 3.11 on Windows. This report describes
the exact pre-alpha implementation and tested boundaries. It is not a safety
certificate, independent audit, publication claim, patent opinion, or proof
that bounded testing can establish universal safety.

## Release outcome

The public package is working for its safely admitted local-first scope. It can
author, migrate, inspect, verify, replay, compare, and share `.sova` behavior
capsules and `.sova-trace` evidence; run controlled browser and process
workflows; discover a finite conditional behavior; coordinate model roles;
execute Arena and rehearsal experiments; perform evidence-linked forensics and
counterfactual reruns; generate evidence, reports, replay media, monitoring,
registry/community artifacts, and extension evidence; and build reproducible
release packages.

The strongest real-runtime acceptance path passed against SOVA's self-owned
loopback website through the installed Microsoft Playwright MCP and Chrome:

1. known-scenario detonation and fresh controlled reproduction;
2. four-candidate bounded trigger hunting;
3. dynamic check followed by a complete offline case workspace;
4. repeated message-removal counterfactual cohorts; and
5. isolated agent-role planning followed by separately approved browser work.

The nine-test browser integration module, including all five opt-in real cases,
passed together in 149.60 seconds. Every target action remained origin-bound,
budgeted, independently authorized, and observable. Snapshot, console, network,
and screenshot digest/size sensors were captured; raw screenshot pixels were
not persisted in traces.

## Operator improvements completed in the final audit

- `sova target browser-kit ORIGIN DEST` creates one inert authoring workspace
  with target, finite campaign, plan, report, and exact control instructions.
- `sova trace command TRACE --working-directory DIR -- EXECUTABLE ARG...`
  supplies the Master-document direct recorder UX while retaining an exact
  digest-bound TTY review, shell refusal, secret-argument screening, and signed
  trace.
- `sova probe issue` and `probe verify` provide a complete offline
  nonce/scope/TTL/key-pin round trip without turning included-key integrity into
  subject identity.
- Real browser scenarios now add screenshot digest/media-type/size evidence
  without placing raw image content in durable traces.
- The bundled demo now enters the same strict case pipeline as live browser
  findings rather than relying on a weaker partial-verification exception.
- Extension execution now recognizes version-suffixed Python, PyPy, and Node
  binaries plus common POSIX shells before rejecting inline-code flags; the
  release matrix also verifies sensor-warning behavior without depending on
  operating-system-specific warning order.

## External-only blockers

These items cannot be truthfully generated by the repository itself and remain
explicitly outside the local completion claim:

1. **A user-selected external website or production software.** It requires an
   exact target supplied by its owner, current proof of control, legal scope,
   test identities/data, target-specific oracles, and interactive approval.
2. **A paid or authenticated model-provider cohort.** `codex login status`
   reported `Not logged in`; no provider credential was read or used. Real
   provider calls remain opt-in and budgeted.
3. **Effectful native desktop UI automation.** Windows-MCP mappings and
   read-only observation are present, but general input is not promoted without
   reliable process/window binding and stronger disposable-session isolation.
   Process testing and browser UI testing are the validated execution lanes.
4. **Independent evidence.** Third-party adapter authorship, cross-organization
   interoperability, blinded labels, security/cryptography/privacy/usability
   review, and larger heterogeneous model/target datasets require independent
   people and systems.
5. **Promoted release authority.** Signed Git tags, transparency-backed package
   provenance, PyPI publication, founder launch approval, and public disclosure
   are separate human release actions.
6. **Longitudinal ecosystem outcomes.** Adoption, hosted registry operation,
   external benchmark comparisons, community CTF content, and monitoring over
   real elapsed time cannot be replaced with fixtures.

None of these blockers permits SOVA to infer authorization, obtain credentials,
bypass CAPTCHA, create unsolicited accounts, conceal actions, persist on a
target, weaken approval, or describe ordinary browser/process restriction as a
security sandbox.

## Release decision

The exact tree is suitable for a public **pre-alpha engineering milestone** and
for controlled evaluation on self-owned or explicitly authorized targets. It
is not a universal autonomous security tester, native-desktop red-team agent,
independent assessor, or stable 1.0 standard. The next external acceptance step
is a founder-supplied owned target and scope, followed by an independently
observed run using the generated browser kit. A promoted release remains HOLD
until the external review and signing gates above are satisfied.
